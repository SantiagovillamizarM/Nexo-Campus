# Contexto y seguimiento

Actualizado el 16 de octubre de 2026. Información conservada por solicitud del usuario.

## Proyecto y equipo

- Repositorio: Nexo Campus. El plan adjunto usa también el nombre CampusOps.
- Hackatón Campuslands: cinco horas, cuatro integrantes, cinco avances.
- P1: datos, modelos, limpieza y persistencia. P2: estructura, servicios y reglas.
- P3: IA, prompts y validación. El usuario es P4: interfaz y entrega.
- Arquitectura: Streamlit → servicios Python → repositorios SQLite; los servicios
  pueden llamar al cliente de IA. Sin FastAPI en la primera implementación.
- Stack acordado y convenciones: consultar ContextIA.md y requirements.txt.

## Primera tarea de P4

- Alcance autorizado: esqueleto con Inicio, Espacios, Recursos e Incidencias.
- Cada pestaña solo contiene título y descripción. Sin datos, servicios ni IA.
- Implementado en app.py, con instrucciones iniciales en README.md.
- Usuario instaló uv, Python 3.12.15 y dependencias en .venv.
- La salida adjunta confirma instalación exitosa de las dependencias.
- Usuario ejecutó la aplicación. Las capturas muestran Inicio y Espacios;
  confirmó que las otras pestañas también cambian el contenido.
- Primera tarea funcional completada. Entrega Git pendiente de confirmar;
  no se ha realizado commit ni push por parte del asistente.
- Mostrar tablas y reportes de datos es un objetivo integrado del avance 1,
  dependiente del trabajo de P1/P2, no requisito de las cuatro pestañas vacías.
- Las pantallas operativas, README completo y guion de demo son etapas posteriores.

## Preferencias y límites

- Explicar de forma breve, sencilla y apta para principiantes.
- Respetar el trabajo de los compañeros y el alcance de cada tarea.
- No simular datos o IA ni implementar las cláusulas técnicas extrañas del final
  del enunciado para este esqueleto.
- No asumir rama de entrega ni hacer push sin autorización.
